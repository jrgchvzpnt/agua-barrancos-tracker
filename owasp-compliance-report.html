F-01

A05 Injection CWE-79

Alto Corregido y re-verificado
Archivo: admin.js:612

Diagnóstico: El teléfono de un mensaje público se interpola directamente en innerHTML. Las reglas permiten que cualquier cliente cree mensajes con un campo phone de texto, por lo que un atacante puede almacenar marcado HTML y ejecutar JavaScript cuando un administrador abre la bandeja. Los campos name y message usan textContent y no presentan este problema en este renderizador.

contactP.innerHTML = `📞 ${msg.phone || 'N/A'} | 📧 ${msg.email || 'N/A'} • 🗓️ ${new Date(msg.createdAt).toLocaleDateString()}`;
Reemplazar la interpolación HTML por nodos de texto: contactP.append('📞 ', msg.phone || 'N/A', ' | 📧 ', msg.email || 'N/A', ' • 🗓️ ', new Date(msg.createdAt).toLocaleDateString());
F-02

A01 Broken Access Control CWE-862

Medio Pendiente
Archivo: firestore.rules:134

Diagnóstico: La regla permite a cualquier cliente crear, cambiar o borrar cualquier documento de analytics; isPublicRead() siempre devuelve true. Esto permite falsificar o borrar métricas y crear documentos arbitrarios, con impacto en integridad y costos.

match /analytics/{docId} { allow read: if isAdmin(); allow write: if isPublicRead(); }
Separar permisos: allow create: if isPublicRead() && validAnalyticsId(docId) && request.resource.data.keys().hasOnly(['visits']) && request.resource.data.visits is int && request.resource.data.visits == 1; allow update: if isPublicRead() && validAnalyticsId(docId) && request.resource.data.diff(resource.data).affectedKeys().hasOnly(['visits']) && request.resource.data.visits is int && request.resource.data.visits == resource.data.visits + 1; allow delete: if isAdmin(). Definir validAnalyticsId para aceptar solo IDs Y_YYYY, M_YYYY_MM y D_YYYY_MM_DD. Aplicar además App Check y su enforcement de Firestore en Firebase Console.
F-03

A06 Insecure Design CWE-770

Medio Pendiente
Archivo: firestore.rules:93

Diagnóstico: La creación de reportes pendientes es pública y valida dateKey, pero no exige que el ID del documento sea igual a dateKey. Un cliente puede crear muchos documentos con IDs distintos para la misma fecha, evitando la deduplicación del frontend y llenando la bandeja administrativa. No hay rate limit del lado servidor.

allow create: if isPublicRead() && request.resource.data.keys().hasOnly(['dateKey', 'status', 'createdAt']) && ...;
Agregar && reportId == request.resource.data.dateKey a la condición allow create; el cliente legítimo ya usa doc(pendingReportsCollection, dateKey), por lo que solo puede existir un pendiente por día. Mantener App Check con enforcement de Firestore y considerar un backend con límites por IP/usuario para frenar abuso automatizado.

A03 Software Supply Chain Failures CWE-1104

Bajo Pendiente
Archivo: admin.html:8

Diagnóstico: El panel ejecuta Tailwind desde su CDN sin versión fijada; Lucide usa @latest en la línea siguiente. Un cambio o compromiso del proveedor/CDN puede modificar el JavaScript ejecutado en el origen del panel, sin revisión del repositorio.
